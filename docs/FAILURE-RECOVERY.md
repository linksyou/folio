# 翻译失败反馈与恢复（LINK-18）

目标是在阅读位置说明翻译结果，并让用户主动补译未完成内容。沿用已有 retry、缓存与取消机制；没有新增自动重试循环，也没有改动 Host 协议版本、模型接入或翻译调度策略。

## 状态与操作

| 页面状态 | 页面与弹窗的反馈 | 主操作 |
| --- | --- | --- |
| 翻译中 | 已翻译段数及首屏优先提示 | 停止翻译 |
| 部分失败 | 成功/总数、失败数和安全原因 | 重试失败段落 |
| 全部失败 | 尚未译出内容、原因和失败数 | 重试未完成段落 |
| 登录、配置或连接阻断 | 明确说明需要处理的连接问题 | 去登录/检查配置/检查连接；另有继续入口 |
| 全部成功 | 当前正文已翻译，新增正文自动继续 | 恢复原文；另有停止持续翻译 |
| 无需翻译 | 单独计数，不视作模型生成成功或失败 | 停止持续翻译 |
| 停止 | 保留成功译文；未请求/已取消内容不计为失败 | 继续未完成内容，或恢复原文 |

悬浮图标仍可拖动并保存位置。贴附的进度按钮可打开状态面板；失败面板自动显示但不抢焦点，关闭后保留文字标记。Escape 关闭面板，仅在焦点位于面板内部时把焦点交回图标。覆盖层位于正文之外，不改变文章布局；支持系统深色和减少动态效果。

全部重新翻译放在更多操作中，并明确提示会忽略缓存、重新生成。取消、恢复和新页面仍依赖既有任务代次、文档身份及响应验证，避免迟到结果写回。

## 实现边界

- `PageTranslator` 区分 `partial`、`failed`、`completed`、`paused`；`skipped` 与未完成内容独立计数。`continuing` 表示是否继续处理新正文，不能从“已完成”推断仍在运行。
- 错误只保留已知错误码对应的固定文案，不显示模型原始响应、地址、密钥或任意异常字符串；未知错误统一为可重试提示。
- `page-feedback.ts` 共同决定弹窗与页面主操作。预检失败也发布到内容脚本，弹窗重新打开时从同一页面状态读取。
- 同时发出的开始/重试请求合并，正在运行的同一任务不重复创建；后台分配了新任务时，页面必须接受新任务身份。相同配置的重试保留仍有效的成功译文节点、原文选区和本页缓存。
- 设置变更使旧译文缓存失效时，继续翻译可能需要重新生成相关正文；不会把不同配置下的结果当作可复用译文。

## 可重复验证

```sh
npm ci
npm test
npm run check
FOLIO_BROWSER_CHANNEL=chrome npm run test:browser
npm run test:native
npm run test:recovery
```

恢复测试默认使用 Playwright Chromium；首次使用可运行 `npx playwright install chromium`。也可设置 `FOLIO_BROWSER_EXECUTABLE` 指定支持加载扩展的 Chrome for Testing 可执行文件。不要指定日常浏览器用户目录；脚本创建独立临时 profile，并在结束时清理。

`test:recovery` 加载构建后的真实后台、内容脚本、弹窗和设置页，使用实际 Chrome 消息、会话存储、页面状态与缓存链路。只将 Native 端口替换为可控模拟响应，并在扩展测试副本中给 `https://folio.test/*` 授权；生产 manifest 不变。正文是固定公开测试文本，没有真实网络模型请求、账号或凭证。结果和截图写入 `test-results/recovery/`。

核心断言包括：

- 固定四段、三段成功、一段网络失败；跨弹窗/页面入口并发重试及运行中重复重试，仅新增一段请求，保留成功译文节点和原文选区。
- 全失败不宣告完成；关闭面板后保留失败标记；重开弹窗后主操作与页面一致。
- 登录失效、配置缺失、Host 错误，以及模拟端口的断连事件均有恢复入口；新文档和同文档 SPA 导航后的预检失败都能在页面恢复。
- 停止保留三段成功译文；恢复原文、真实页面导航后迟到响应不写回；目标语言段落在停止后仍计为无需翻译。
- 动态新增正文继续翻译；键盘操作与可见焦点、保留输入框焦点、拖动不触发翻译、浅/深色、360px 窗口、200% 浏览器缩放和减少动态效果。
- 原有页面回归另含新任务接管测试：相同任务重试不重复请求，新任务身份替换正在运行的旧任务，旧响应不得覆盖新译文。

本机验证使用 Chrome / Chrome for Testing 156 和 Node 26。单测与隔离浏览器结果是功能回归证据，不代表真实服务成功率或提速。尚未验证 Edge、真实登录/模型、日常安装的 Native Host 与扩展完整通信、工具栏授予 activeTab 的权限流程，以及人工读屏器体验。Native Host 与 HTTP/SSE 通信另由 `test:native` 的隔离模拟服务测试覆盖，不能将两组独立测试描述为真实账号端到端验收。
