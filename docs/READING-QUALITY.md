# 阅读质量、动态更新与缓存验证

2026-11-12，基线为 `fa7da20`。环境为 macOS arm64、Node 26.8.1、Chrome 156.0.8078.81、1280 × 720 视口。以下测试使用隔离页面、模拟服务和临时 Host 数据目录，不读取个人账号或调用真实模型。

## 用户可见的变化

- 尊重继承的 `translate` 属性和 `.notranslate`。行内 `code`、`kbd`、`samp`、MathML、`role="math"` 以及免翻译文本在页面内保存，模型只接收编号占位符。流式显示会等待完整占位符再恢复文字；完整结果若遗漏、重复或伪造编号，则该批失败且不写缓存。原始 DOM 不被替换，公式在译文中保留文字，原公式排版保留在原文中。
- 只有网址或邮箱的段落不再发送。声明的 main 全部只有短文本（每段不足 24 字符）时，若另一个 article 有至少 80 字符的候选段落，采用 article；有效 main 仍保留原有范围。
- 可见、预读、后台优先级从页面贯通到 Host 等待队列。同级保持顺序，最多八次插队后服务最早的等待请求。正在生成的请求不抢占，已共享的在途请求不重新排队。
- 已知较长 P 段落的纯文字修改局部重新提取，未变段落不重复发送；结构、属性、短文本、正文候选根和混合 main/article 布局继续全量发现。立即失效与取消旧请求的检查保留。局部提取仍会遍历已有段落的元数据，不宣称整个更新为常数时间。
- 同批缓存一次读取，最多 256 个热点条目留在内存中。命中不等待访问时间写回；访问记录在下一次缓存写入或统计时刷新。TTL、容量、清除顺序与清除后的迟到结果保护保留。每次写入仍会做容量修剪，浏览器进程结束前未刷新的访问时间可能丢失，但译文本身不受影响。
- 缓存身份忽略常见 `utm_*`（source/medium/campaign/term/content/id）、gclid/fbclid 参数和已确认存在对应 DOM 元素的锚点。保留内容查询参数、未知 hash、`#/` 和 `#!` 路由。修改未启用 provider 的配置不改变生成版本；当前模型、密钥、目标语言和账号变化仍使旧工作失效。

提示词版本由 1 升为 2，旧缓存不会被本版复用；旧条目仍按原有过期/清理策略处理。更新需要同时重建 Host 与扩展并重新加载，见 README。

## 批量缓存容量回归修复（2026-11-13）

审阅 `06dab57` 时发现：存储已有 257 个译文，按顺序预热 `0..255` 后读取 `[256, 0, 1]`，第 256 项进入热点 LRU 时会淘汰第 0 项。第 0 项仍在持久存储中，但它在批次开始时属于热点，未进入本次存储读取，因而被误判为未命中；服务不可用时整批请求失败。

`TranslationCache.getMany()` 现在先保存本批热点条目，再加载本批冷项，最后从完整快照读取并更新 LRU。热点仍限制为 256 项，只向存储请求去重后的冷键，访问时间仍延迟写回。

本轮环境为 macOS arm64、Node 26.8.1、Chrome 157.0.8103.51，测试继续使用隔离数据和模拟服务。

- 新增 10 项自动化回归，分别覆盖批量存储和逐键读取回退：255/256/257 项预热边界、600 项混合批次、重复键与真实未命中、热点容量上限，以及 `TranslationReuse` 在服务不可用时返回全部缓存译文、进度及原始顺序。真实未命中仍正常报告服务错误。
- 相同新增用例在修复前为 2 项通过、8 项失败；修复后 `npm test` 全部 **121 项通过**，`npm run check` 通过。
- 新增 Chrome/IndexedDB `cache-capacity` 回归：相同 257 项缓存和三段读取在修复前因误调用模拟服务而失败，修复后完整返回三段译文，模型层调用 **0 次**，持久存储保留 257 项。原有 46 个提取样本、10 类交互回归和 12 段页面缓存验证也通过。
- 在 `npm run check` 生成的构建产物上执行 `npx tsx scripts/test-native.ts`，HTTP/SSE、未启用服务配置保存、占位符拒绝及当前配置变更取消回归通过。

复现命令：`npx tsx --test tests/cache-batch.test.ts`、`FOLIO_BROWSER_CHANNEL=chrome npm run test:browser`。这次验证针对缓存命中正确性与额外请求，未重测下述 30 轮性能数据，也不代表真实模型或安装态扩展完整链路已验收。

## 相同条件的性能对照

每个条件 30 轮，保留全部样本，按 nearest-rank 计算。页面基准为固定 12 段，模拟首片段 12 ms、完成 25 ms；首段测可见 DOM 文本，不是 paint。统计方法见 [PERFORMANCE.md](PERFORMANCE.md)。

| 指标 | 基线 p50 / p95 | 本版 p50 / p95 |
|---|---:|---:|
| 静止、未命中：首段 | 21.8 / 24.2 ms | 21.6 / 22.3 ms |
| 静止、未命中：固定首屏 | 64.1 / 65.2 ms | 64.0 / 65.4 ms |
| 静止、未命中：整页 | 270.5 / 382.8 ms | 268.9 / 275.5 ms |
| 静止、命中：首段 | 4.4 / 10.7 ms | 5.9 / 6.9 ms |
| 静止、命中：固定首屏 | 5.3 / 12.4 ms | 4.8 / 6.0 ms |
| 静止、命中：整页 | 12.1 / 23.6 ms | 12.7 / 14.4 ms |
| 滚动、未命中：新屏首段 | 29.0 / 37.0 ms | 28.9 / 30.5 ms |
| 滚动、未命中：新屏完成 | 73.0 / 80.9 ms | 72.3 / 75.6 ms |

修改前后各 120 个页面运行均完成 12 段：60 个未命中运行各调用模拟 provider 12 次，60 个命中运行零调用。总体中位数接近，缓存首段中位数略升；不能据此宣称全面提速。尾延迟降低只描述本组样本，不作真实服务承诺。

另用同一个 fixture、同一个浏览器测 1000 个已经是目标语言的长段落，每轮只修改一个 Text 节点，排除模型调用干扰。基线和本版各 30 轮：

| 动态发现指标 | 基线 | 本版 |
|---|---:|---:|
| 重新提取的候选数 | 1000 | 1 |
| 扫描与协调 p50 / p95 | 6.0 / 6.8 ms | 1.8 / 2.1 ms |
| 最终保留段落 / 模型调用 | 1000 / 0 | 1000 / 0 |

动态耗时包括重新提取及块协调，不包括 50 ms 防抖等待、MutationObserver 的即时校验或绘制。短段落、增删节点、属性更新仍全量扫描。本轮没有改变错误重试策略，也没有增加 iframe、Shadow DOM、PDF 或 OCR 支持。

## 复现

```bash
npm ci
npm run check
npm test
npm run test:native
FOLIO_BROWSER_CHANNEL=chrome npm run test:browser
FOLIO_BROWSER_CHANNEL=chrome FOLIO_BENCHMARK_ROUNDS=30 npm run benchmark:browser
FOLIO_BROWSER_CHANNEL=chrome FOLIO_BENCHMARK_ROUNDS=30 npm run benchmark:dynamic
```

动态对照可在另一个目录导出基线的 `src/`，设置 `FOLIO_BENCHMARK_SOURCE` 指向该目录，再用当前 fixture 运行 `benchmark:dynamic`。每次运行覆盖 `test-results/performance-dynamic.json`，需先保存前一份。页面运行生成 `test-results/performance-browser.json`，回归生成 `test-results/browser-regressions.json`；生成文件不进 Git。
