# Open Web Translator

Open Web Translator 是一个开源的 Chrome／Edge 网页双语翻译扩展。用户点击“翻译正文”，或为当前网站启用自动翻译后，扩展识别当前页面的正文，通过 ChatGPT 或自定义 API 翻译成所选语言，并逐段显示。原链接、代码和页面事件不会被替换，用户可以停止、重试失败段落或恢复原文。

当前版本面向本地开发和验证，尚未发布到扩展商店。

## 当前能力

- 普通 HTTP／HTTPS 文章和技术文档正文
- 简体中文、繁体中文、英语、日语、韩语、法语、德语、西班牙语目标语言；双语或仅译文显示
- ChatGPT 登录、多账号切换和按账号缓存的模型目录
- ChatGPT 与自定义 API 的思考强度选择；默认优先速度
- OpenAI Chat Completions 兼容的自定义 API
- 当前视口优先、同屏短段合批流式预览、方向性预取、停留和切换标签页时继续翻译其余正文、停止、失败批次重试和恢复原文
- 按连续原文节点定位译文，保留嵌套列表、表格单元格和 Flex/Grid 段落所在位置
- 动态正文发现、改文重新翻译、同源 SPA 切页自动衔接
- 跨刷新本地译文缓存、同页地址下的重复请求合并，以及保守的目标语言过滤
- 双语/仅译文和译文样式独立保存，修改后立即应用到已翻译页面
- 分组设置页、简洁工具栏小窗与可拖动贴边的网页悬浮工具，支持深浅色、键盘操作和减少动态效果
- 按网站授权的自动翻译，以及 Alt+A 翻译、Alt+R 恢复原文快捷键
- 本地辅助程序复用同源 TLS／HTTP 连接，减少阅读和滚动期间重复建连
- 打开弹窗时预热所选服务，点击翻译时复用连接；预热不发送正文、凭证或模型生成请求
- Chrome／Edge 桌面端；安装器支持 macOS 和 Linux

## 安装

需要 Node.js 22.12 或更高版本。

```bash
git clone https://github.com/linksyou/open-web-translator.git
cd open-web-translator
npm ci
npm run check
npm run install:host -- --browser chrome
```

随后在 Chrome 中加载扩展：

1. 打开 `chrome://extensions`。
2. 开启“开发者模式”。
3. 点击“加载已解压的扩展程序”。
4. 选择本项目的 `dist/extension` 目录。

Edge 的安装命令和扩展页分别是：

```bash
npm run install:host -- --browser edge
```

打开 `edge://extensions`，加载同一个 `dist/extension` 目录。若同时使用 Chrome 和 Edge，可将 `--browser` 设为 `all`。

安装脚本把自包含的 `dist/host/main.cjs` 和启动脚本复制到 `~/.local/share/open-web-translator/host/`，浏览器在需要时自动启动本地辅助程序。日常使用不需要保持终端窗口运行。

### 更新已安装的开发版

修改源码后运行 `npm run check`；涉及本地辅助程序或跨进程协议时，再运行对应浏览器的 `npm run install:host` 命令。然后在浏览器扩展管理页点击本扩展的“重新加载”，并刷新已经打开的设置页和待翻译网页，让它们载入新版脚本。重新安装本地程序会保留已保存的账号和设置。

## 连接模型

打开扩展设置页，选择一种连接方式。

### ChatGPT

点击“Continue with ChatGPT”，在浏览器中完成授权，再从当前账号返回的模型目录中选择模型并测试连接。设置页会按本地 profile 保留本次打开期间读到的目录；本地辅助程序还会按 access token 分区短暂缓存目录，切换账号时不会混用结果。

“思考强度”默认是“自动（速度优先）”。对能力已知的模型，程序选择它支持的最低档；对能力未知的模型，程序省略 `reasoning`，交给服务端使用模型默认值。手动选择只显示目录或内置能力表明确支持的档位；如果旧设置保存了当前目录未声明的档位，界面会保留并明确标注，不会静默改写。

该接入目前属于 OpenAI 提供的预览能力，能否授权、可用模型和用量取决于账号的官方资格与当前服务状态。当前已有资格的真实账号已用 `gpt-6-luna` 和 `auto` 完成一条短句推理验证；这只证明该账号当时的登录、模型请求和流式返回链路可用，不代表所有账号均可使用，也不构成整页翻译质量验收。

### 自定义 API

填写 API 基础地址、API Key 和模型 ID。首版只支持 OpenAI Chat Completions 兼容文本协议。自定义 API 的思考强度选择“自动”时不发送 `reasoning_effort`，避免破坏不认识该参数的兼容服务；手动选择时才发送，是否支持由目标接口和模型决定。

基础地址应类似：

```text
https://example.com/v1
```

程序会请求 `${customBaseUrl}/chat/completions`，因此不要在基础地址中重复填写 `/chat/completions`。远程地址必须使用 HTTPS；本机 `localhost`、`127.0.0.1` 和 `::1` 可以使用 HTTP。API Key 可以留空，以连接无需认证的本机服务。

## 网页悬浮工具

在已手动开始翻译的网页、或已授权自动翻译的网站，页面边缘显示淡色书页图标。**点击直接翻译，再点显示原文**；恢复原文会停止本页的动态续译，再次点击可复用有效缓存。悬浮入口没有展开面板或其他操作。

按钮平时淡化，悬停和键盘聚焦时稍微显现；可以拖动到左右边缘并记住位置，在设置页的“悬浮工具”可关闭。没有授权的其他网站不会出现悬浮按钮。图标复用现有 `icons/icon-32.png`，仅将这一静态图片声明为网页可访问资源，不新增网站访问权限。

## 使用

1. 打开一篇普通网页文章。
2. 点击扩展图标，再点“翻译正文”。
3. 扩展优先翻译当前屏幕。屏内最多 3 个短段合为一次流式请求，译文随输出逐段出现；屏外每批最多 2 段。屏内及附近内容完成后，以一个请求继续翻译页面其余正文；停留阅读或临时切到其他标签页时也会继续。滚动或返回页面后重新优先当前屏幕，有新屏内内容等待时才取消远处请求。总并发仍不超过 2，长段按块处理。
4. 翻译期间可以关闭弹窗；重新打开后会显示进度。动态追加正文、修改原文和同源 SPA 切页会自动衔接。点击“停止”或“恢复原文”会停止当前页面自动衔接。
5. 失败段落可以重试。“恢复原文”移除译文并还原隐藏原段，再次普通翻译可复用有效缓存。默认还会缓存完整译文，刷新后相同页面地址、原文和生成配置可直接复用；“重新翻译”清空本页内存缓存，绕过持久缓存、旧在途请求及语言过滤，重新调用模型。
6. 在弹窗开启“此网站自动翻译”，允许浏览器访问该网站后，新页面和刷新会自动开始。此规则按 origin 保存（协议、主机和端口），不默认申请所有网站。关闭开关会停止该站任务并撤销该站可选权限。当前页面恢复原文后不会立即重启，刷新则按网站规则重新开始。
7. 目标语言随模型配置保存，用于新任务。双语/仅译文在“阅读与显示”中独立自动保存，修改后立即应用到已翻译页面，不重新生成译文。“仅译文”在译文完整完成后隐藏简单原段；含链接、嵌套列表等交互或复杂结构保留双语，以保护原页面功能。
8. `Alt+A` 开始翻译，`Alt+R` 恢复原文。可在 `chrome://extensions/shortcuts` 调整键位；系统或浏览器冲突可能需要改键。
9. 设置页的“阅读与显示”提供侧边线、淡色背景、下划线和纯文本，以及 90%、100%、110%、125% 字号。可以分别自定义译文文字颜色和背景颜色，选色时实时预览并自动应用到已翻译网页，无需重新翻译。自定义颜色适用于所有装饰样式，切换浅色/深色主题时保持选择；颜色旁的“默认”按钮恢复该项配色，“恢复默认”重置全部外观设置。这个外观设置同时用于双语和仅译文模式。

默认译文样式为纯文本、100% 字号、文字颜色 `#4A9834`、透明背景，浅色与深色模式使用同一文字颜色。首次使用和“恢复默认”均采用这套配置，文字颜色旁的“默认”按钮也恢复为 `#4A9834`。

设置页“翻译缓存”可以关闭持久缓存、清除全部缓存或按网站清除；关闭后已有记录仍保留，可另行清除。清除不移除已显示的译文。无痕页面不读取或写入持久缓存，也不与其他页面共享模型请求。

本地语言过滤会保留有足够证据已是目标语言的原文，进度中单独显示“无需翻译”，不算作生成完成。短标题、名字、未知文字和混合语言仍可能提交翻译；简体与繁体分别判断，英文等拉丁语言还需要匹配的网页 `lang` 线索。原文或语言线索改变后重新判断，强制重译可绕过过滤。

开始后会逐步处理当前页面已加载的全部可翻译正文，也会处理随后新增的正文，因此用量可能多于只阅读首屏。后台继续限于页面仍存活且浏览器允许运行的情况；冻结、丢弃标签页、关闭浏览器或系统睡眠时不保证继续。扩展不会为此自动滚动或触发网站加载更多，点击“停止”即可终止后续调度。

正文会发送给设置页当前选中的模型服务。项目不运行运营方云服务器。本地辅助程序平时只通过浏览器的 Native Messaging 标准输入输出通信；ChatGPT 登录期间会临时监听 `127.0.0.1` 回调，授权结束后关闭监听。

打开弹窗并读到有效配置后，扩展会提前连接所选服务，在弹窗显示准备状态。冷连接预热向服务根地址并发发送两次不带鉴权和正文的 `OPTIONS`，为现有两个请求槽准备连接，不调用模型；服务会看到这两次普通网络访问。已有连接时跳过额外探测。点击翻译时复用已建立的连接；如果准备尚未完成，前台最多等待 250 ms，再取消慢探测并发送正常请求。预热失败也会正常尝试翻译，不因此重复发送生成请求。

本地辅助程序会在普通阅读停顿期间保留 Native Messaging 连接和自己的 HTTP 连接池，当前空闲期为 60 秒。本机受控短句测量中，冷连接准备约 5.50 秒，准备完成后点击到首字约 1.69 秒；15 秒后再请求约 1.56 秒。这些历史样本使用完成后的预热连接；新版本提前点击会受 250 ms 等待预算约束，必要时重新建连，仍存在冷 TLS 和模型等待，不能承诺固定“秒开”。测量边界和复现实验见[延迟诊断](docs/LATENCY.md)。

## 本地数据

默认数据目录是：

```text
~/.local/share/open-web-translator/data
```

ChatGPT token、自定义 API Key 和设置保存在本机权限为 `0600` 的 JSON 文件中，目录权限为 `0700`。这是操作系统文件权限保护，不是系统钥匙串加密。凭证不会发给网页，也不会写入仓库或正常错误信息。

显示方式、译文样式、缓存开关和按站自动翻译规则保存在当前浏览器的扩展本地存储中。显示修改不会改动模型配置版本、清空译文缓存或重发已有段落的翻译请求；保存相同的生成配置也不会使缓存失效。

完整译文另存于扩展的 IndexedDB，默认从写入起保留 30 天、最多 2000 条，并按约 5 MiB 的记录大小预算淘汰最近最少使用的记录。缓存按网站、完整页面地址、原文、生成配置版本及翻译指令版本隔离；只保存组合指纹、网站 origin、译文和时间/大小信息，不保存明文原文、完整 URL 或凭证。译文本身仍可能含私密内容；可在设置页关闭和清除缓存。浏览器存储清理或卸载扩展也可能移除这些记录。

卸载本地辅助程序时保留用户数据：

```bash
npm run uninstall:host -- --browser chrome
```

若要清除本地数据，需要由用户另行删除数据目录。

## 首版边界

当前不支持 PDF、iframe、Shadow DOM、移动端、OCR 和视频字幕。跨刷新缓存只复用同一完整页面地址与生成配置下的相同文本，不跨不同文章地址共用译文。动态发现采用合并触发的正文扫描与稳定节点登记，复杂或频繁变化的网站仍需专项性能验证。仅译文模式对交互原段保留双语。自定义流式服务必须正常结束并返回完整合法段落；只有服务明确不支持流式时才降级普通请求。

弹窗的“导出性能记录”生成本地 JSON，记录有限容量的点击到首个可见译文、提取、排队、认证、请求派发、首个增量、视口完成和取消事件。记录不含正文、网站 URL 或凭证。服务未返回的用量保持未知，取消也不代表零用量。
